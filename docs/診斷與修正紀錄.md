# 為什麼一課反覆調整，以及這次修正了什麼

對象是維護本專案的教師與製作助理。使用者回報一課約需 2–3 天；本次沒有取得製作工時或逐輪操作紀錄，因此不能把每項問題換算成耗時，也不能宣稱已縮短到幾小時。

檢查版本：本專案 `7442851e7bf240916b86bc9beeac0f2cdaab3cbc`。原始系統只讀參考版本 `5a6e8d85c0c48c9238b4322a58d58fdf8187b226`，沒有修改原始系統。

## 已證實的重工來源

1. **輸出檔名會碰撞。** KN4 L3 製作表第 93／95 行都指定 `slide-52.html`；106／107 行都指定 `slide-63.html`。前者內容近似但不同，後者分別是功能練習與團體任務。若產生器依檔名寫入，後寫內容會覆蓋前者。這是已證實的輸入缺陷；是否曾在朋友本機發生覆蓋，仍需實際輸出確認。
2. **內容清單與總數分開維護。** KN2 L2 宣告 54 頁、實際 57 列，QA 又勾選 56 頁。KN4 L2 有 60 個製作列，但混用跳號與 `49.1` 等插頁編號。這些格式與 `slide-XX.html` 連續命名規則不一致。
3. **版面驗收互相衝突。** 共用邊界是 27 px，生詞右卡又被要求距畫布 10 px；22 pt 字級與 42 px 字形目標混在一起。這會讓一次符合某份文件的修改，違反另一份文件。
4. **拆頁後仍可能不過 QA。** 規則要求溢出先拆頁，檢查卻仍要求每頁 3–5 題和一個語法一頁。長對話拆完只剩兩題時，助理可能再縮字或補題。
5. **內容審核被混入尚不存在的畫面驗收。** 工作流程在教師審核階段要求 DOM／截圖，再於通過後製作 HTML。已改為先審詞彙與內容，HTML 初稿後量測版面。
6. **重新生成沒有保護上一版。** 舊流程先清除 slide 檔，再生成與檢查；途中失敗會失去可用版本。已改成暫存生成、驗證後切換的操作規格，尚未在朋友的本機產生器實作。
7. **規則缺乏入口與權限範圍。** 本專案沒有自己的 AGENTS.md 或 SKILL.md；詳細規則散在兩套課程及各課稿件中。上游另有個人偏好與不同工作方法，直接混用容易把課程工作帶回另一套流程。

## 參考系統能說明的風險

原始系統的 `scripts/validate-system.mjs:248-251` 用 `f.split('-')[0]` 取得頁碼，適用它的數字開頭命名，但不適用這裡的 `slide-XX.html`。以 `slide-01.html, slide-03.html, slide-03.html` 重現，取得的數字陣列為空，連號檢查仍回傳通過。不能把上游 validate 的通過直接當本專案連號證據。

原始 skill 的 small-edit 段落建議小修可直接改產出 HTML；若朋友照做而沒回寫來源，下次重建就可能遺失。這是條件性的風險，未取得朋友實際 skill 與重建紀錄，不宣稱他一定使用了這段指示。

原始 `create-teacher-deck.mjs` 是另一套頁名與內容安排，包含固定的示例內容；它不是本專案 50–67 頁 KN2／KN4 製作表的直接替代產生器。不能靠換回上游就保證解決。
