# 教材包格式與生成流程

這份文件說明教材包（慣例副檔名為 `.lesson.json`）如何進入課程編輯器，以及命令列批次路徑如何保留上一版版面。教材包保存原教材與本課內容資料庫；它不是教師核可證明，也不是直接可放映的投影片。

## 正式入口

新課按根目錄 `index.html` 的「新課程」。系統會建立新的教材包並開啟「教材與課程資料庫」；生成前投影片畫布與格式工具保持鎖定。按以下順序操作：

1. 在「原教材與頁碼」讀取 `.txt`／`.md`，或用「讀取文字教材 / 教材包」匯入 `.lesson.json`。也可以在欄位中逐頁貼上原文，填入教材名稱與課本印刷頁碼後保存。
2. 每個來源頁都要對照原教材，再按「已對照原頁，確認文字與頁碼」。修改頁面文字會清除該頁 `reviewedText`，必須重新核對。
3. 在「課程內容」新增教材內容或練習，指定來源與原教材頁碼，填寫題型、學習目標、學生操作說明、正文／題幹、答案／背面與超綱標注。補充題也要連結教材或教師補充依據。
4. 逐項勾選核對內容並按「記錄本項內容已核對」。核對包含題目與答案、簡體中文／越南語、課程程度、超綱標注與學生操作說明；自動生成或程式通過不等於教師核可。
5. 全部必填欄位、來源頁、內容核對與結構檢查通過後，按「核對完成，生成 PPT」。生成後才可拖曳、改文字、加圖或調整版面。

舊製作稿匯入只接受含 `頁碼`、`檔名`、`投影片畫面文字` 欄位的 Markdown 表格。它會保留所有列與原文備註，作為待溯源文字草稿；不會重建舊版面、圖片、互動或答案，也不能繞過教材來源與內容核對。未核對資料仍可下載備份，但不能正式放映或匯出。

## `.lesson.json` 格式

教材包根層欄位如下：

| 欄位 | 必要條件與用途 |
|---|---|
| `schemaVersion` | 目前固定為數字 `1`。 |
| `id` | 課程包 ID；須為 1–100 字元的英數、`-` 或 `_`，同一課重建時要保留，才能套用 `previous.slides.json` 的版面。 |
| `title` | 課名，不能空白，最多 500 字元。 |
| `course` | 只能是 `KN2` 或 `KN4`。 |
| `sources` | 原教材來源陣列。每個來源要有唯一 `id`、`name` 與至少一頁 `pages`。 |
| `sources[].pages[]` | `number` 是原教材印刷頁碼，`text` 是該頁文字；同一來源頁碼不可重複。`reviewedText` 初始為 `null`，教師對照原頁後才保存與 `text` 完全相同的文字。PDF 可另保留 `pdfPage`；原檔可保留 `sha256`。 |
| `vocabulary` | 可選的詞彙查詢資料；抽取器會從本倉庫單字資料庫帶入，不能代替本課內容核對。 |
| `items` | 本課內容資料庫。抽取器刻意輸出空陣列，必須由 UI 或教師／AI 依課本整理後再逐項核對。 |

每個 `item` 使用以下欄位：

| 欄位 | 必要條件與用途 |
|---|---|
| `id` | 全教材包內唯一且穩定；頁面重建與版面覆寫依此對應。 |
| `type` | `cover`、`content`、`vocabulary`、`grammar`、`exercise` 或 `task`。 |
| `origin` | `textbook`、`supplement` 或 `legacy`。舊稿先標 `legacy`，補齊來源與內容後再整理。 |
| `sourceId`、`pages` | 指向 `sources` 與原教材印刷頁碼。補充練習也要有可追溯的依據。 |
| `objective` | 本頁學習目標，寫學生完成後能做什麼。 |
| `exerciseType` | 練習／任務使用已定義題型，例如 `completion`、`dialogue`、`speaking`；其他頁型仍保留字串欄位。 |
| `exception`、`notes` | 教師指定例外、待核對事項與製作備註。 |
| `review` | 未核對為 `null`；UI 核對後由程式寫入指紋與時間，不要手填假造核可狀態。 |
| `blocks` | 頁面內容陣列。每個 block 有全包唯一 `id`、`role`、`type`、`text`、`backText`、`annotations`。可用 role 包含 `title`、`instruction`、`explanation`、`pinyin`、`body`、`examples`、`extra`。 |

練習與口語任務的 `body` 必須使用可揭示的 `type: "reveal"`，答案放在 `backText`；生詞頁的生詞卡使用 `type: "flashcard"`，背面只放兩行越南語詞性與越南語翻譯。超綱標注放在 `annotations`，每筆要有正文中的 `word`、`pinyin` 與 `vi`。程式檢查欄位、來源、題型、正反面與可檢查的版面條件；語意、程度、答案正確性與教學安排仍由教師判定。

可匯入的完整範例見 [未核對功能示範](../examples/workflow-demo.lesson.json)。它不是實際課本內容，來源與項目核對初始均為空；先由 UI 核對才可生成，不能當成已核可的教案。

## `prepare_lesson_package.py`：可選命令列抽取

命令列是批次整理路徑，UI 也可以直接讀取文字教材或教材包。腳本只支援 PDF、TXT、Markdown；PDF 需要系統有 `pdftotext`（Poppler）。

```bash
python3 scripts/prepare_lesson_package.py "教材.pdf" \
  --title "KN2 L2 晚上早点儿睡" \
  --course KN2 \
  --page-labels "13,14,15" \
  --pdf-start 1 \
  --pdf-end 3 \
  --output "KN2課堂PPT/L2_晚上早点儿睡/L2.lesson.json"
```

參數規則：

- `source` 是現有的 PDF、TXT 或 Markdown 檔案。
- `--title` 與 `--course` 必填；`--course` 只能是 `KN2`／`KN4`。
- `--page-labels` 必填，依抽取順序以逗號分隔，數量必須與抽取頁數相同、不可重複，且要填課本印刷頁碼；不要從 PDF 頁序猜課本頁碼。
- `--pdf-start` 預設 `1`；`--pdf-end` 可限定原生 PDF 頁面範圍，不能小於起始頁。
- `--output` 必填。輸出檔已存在或與來源相同時會停止，藉此保留上一版。

PDF 以 `pdftotext -layout -enc UTF-8` 抽取，文字以換頁符分頁；TXT／Markdown 也以換頁符分頁。任何頁面沒有可抽取文字時，腳本會停止並要求先 OCR、再對照原頁；它不會從掃描影像猜測文字。輸出包含來源檔名、雜湊、每頁文字與空的 `reviewedText`，並帶入詞彙查詢資料，但 `items` 一定是空陣列。抽取完成只代表保存來源，訊息會標示「尚未核對、尚未生成課程」。

## UI 核對與生成／交付檢查

教材包載入後，UI 會讓來源頁與課程內容分開核對：

- 來源頁必須有非空文字；按確認後 `reviewedText` 必須等於目前 `text`。原文一改就回到待核對。
- 每個 item 必須能連回來源頁，並有穩定 ID、頁型、目標、正文、必要學生指令、答案／背面與超綱標注欄位。練習與任務要有已定義題型；生詞要有拼音、例句與兩行卡片背面。
- 按「記錄本項內容已核對」前，教師要實際對照課本，確認語意、程度、答案、簡體中文／越南語、超綱詞與學生能否直接執行。程式會保存內容指紋；內容、答案、指令、來源或標注修改後，指紋不再相符，項目回到待核對。
- 按「核對完成，生成 PPT」時，UI 會拒絕缺來源、缺必填內容、未核對 item 或不合格式的教材包。生成後才解除畫布與格式工具鎖定。
- 正式放映、匯出與列印前的交付檢查會量測正面及翻牌／答案背面的文字是否放得下、是否超出安全區；失敗時放大文字框或依題目順序拆頁。程式檢查這些可量測條件，不宣稱自動判斷全部教學品質。
- 「下載教材包與資料庫」可在未核對時保存 `.lesson.json` 備份；備份不代表可放映。通過核對與交付檢查後，才可開始放映、匯出 HTML 或列印 PDF。

生成後直接在投影片上改文字或新增內容，下一次交付檢查會把變更回寫對應 item 並使核對失效；重新生成前要回到教材資料庫核對。單純拖曳、縮放、層次與樣式修改保存到 `layoutOverrides`，不清除內容核對，且下一次重建要套回這些版面修改。

## `build_course.cjs`：可選批次生成與上一版版面

命令列用法：

```bash
node scripts/build_course.cjs INPUT.lesson.json OUTPUT.slides.json [PREVIOUS.slides.json]
```

- `INPUT.lesson.json` 是已整理並核對的教材包，不是任意 Markdown 或舊 HTML。
- `OUTPUT.slides.json` 必須使用新檔名；檔案已存在時腳本停止，不覆寫上一版。
- `PREVIOUS.slides.json` 可選，用來承接同一教材包的上一版手動版面。教材包 `id` 必須相同；每個 item 的穩定 `id` 也要保留，`layoutOverrides` 才能套回對應頁面與物件。重新抽取而產生新 package ID 時，先保留原 package ID／檔案並在其上更新內容，否則腳本會拒絕套用上一版版面。
- 沒有 `previous` 時，腳本從教材包建立新投影片；有 `previous` 時，先讀取舊 JSON、保存已記錄的版面覆寫，再由教材包重新生成。生成輸出仍會保留教材包、來源、items、slides 與版面資料。
- 腳本會驗證教材包並檢查生成結果、內容對應、安全區與可交付條件；瀏覽器 UI 在正式匯出／放映前再量測每頁正面與背面文字溢出。建置失敗時使用上一版，不能用不完整輸出取代可用版本。

內容與版面分開保存：修改課本來源、題目、答案、學生指令或新增練習，要更新 `sources`／`items`、使受影響核對失效，再重建；修改位置、尺寸與樣式，保留在 `layoutOverrides`，重建時保留。舊 `.slides.json`、製作稿與 `legacy` item 可持續下載備份與整理，未補齊來源及核對前不得標為正式課程。
