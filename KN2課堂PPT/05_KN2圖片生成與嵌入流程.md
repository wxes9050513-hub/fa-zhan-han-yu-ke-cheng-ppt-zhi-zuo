# KN2 圖片生成與嵌入流程

本流程用於 KN2 課堂投影片的圖片生成、下載、裁切、加入與 QA。舊產生器路線在 `HTML_PPT製作稿` 定稿後進行；editor 路線必須先完成教材包、來源與 `items` 核對，再在 UI 生成或由可選 `build_course.cjs` 生成的 `.slides.json` 中加入圖片。不用圖片的課次可略過；圖片不能繞過內容來源或教師核對。

## 1. 適用範圍

需要納入本流程的素材包含：

- 封面圖、下課頁或情境圖。
- 生詞頁 `Từ vựng` 的輔助小圖或 icon。
- 功能句、補充辨析頁的人物或情境圖。
- 圖片造句練習頁。
- HTML/CSS 暫時畫出的視覺元素。
- 暫用 SVG、placeholder 圖。
- 任何之後要用 ChatGPT 圖片取代的頁面視覺元素。

KN2 L1 目前需特別納入圖片需求表的暫用 SVG 包含：

| 頁碼 | 目前暫用素材 | 用途 |
|---|---|---|
| P1 | `slide-01-cover.svg` | 封面右側新地方生活情境圖。 |
| P14 | `slide-11-guide.svg` | `导游` 生詞小圖。 |
| P17 | `practice-pho.svg`、`practice-coffee.svg`、`practice-phone-game.svg`、`practice-hotel.svg` | `好 + Adj.` 四格圖片造句練習。 |
| P25 | `type-c.svg`、`lightning.svg`、`usb.svg` | `充电器／充电` 接頭輔助圖；Type-C、Lightning、USB 字樣由 HTML caption 排版，不放進圖片。 |

## 2. 圖片需求表

生圖前先整理圖片需求表。舊產生器路線寫入該課 `HTML_PPT製作稿`；editor 路線先把圖片用途、來源與對應 `item` 記在教材包／素材資料，教師確認裁切素材後再加入已生成的 `.slides.json`。若由 Markdown 匯入，只接受含 `頁碼`、`檔名`、`投影片畫面文字` 欄位的 HTML_PPT 製作表，且只建立待溯源文字草稿，不能取代教材包核對。

| 欄位 | 說明 |
|---|---|
| 頁碼 | 對應投影片頁碼，例如 P12。 |
| 檔名 | 建議格式：`slide-{{page}}-{{role}}-{{keyword}}.png`，需能一眼看出對應 PPT 頁碼與用途。 |
| 頁型 | 封面、`Từ vựng`、圖片造句、功能句等。 |
| 用途 | 封面主圖、單字 icon、SVG 替換、HTML/CSS 視覺替換、圖片造句情境圖等。 |
| 視覺內容 | 具體描述畫面，不寫抽象詞。 |
| 生成方式 | 單張圖或 contact sheet 批次。 |
| 建議比例 | 封面可用橫式；生詞小圖、icon 優先方形。 |
| 放置位置 | 例如右側例句下方、左側圖片區、封面右側圖框。 |
| QA 注意 | 是否避開文字、是否可能切到相鄰格、是否需替換舊 SVG。 |

### 生詞頁補圖判斷

生詞頁補圖不是預設必做；整理圖片需求表時先判斷空間與教學必要性，再決定是否列入生圖。

- 優先補圖：具體名詞、具體物品、明確動作、生活／校園場景詞。
- 不優先補圖：抽象詞、語法性強的詞、功能詞、已可由例句清楚理解的詞。
- 右側例句或 AB 對話下方可用高度約 `140px` 以上，才可考慮放約 `180px x 110px` 的小型輔助圖。
- 可用高度約 `90px` 到 `120px` 時原則上不補，除非教師指定。
- 不得為了補圖縮小例句、壓縮行距、改壞超綱標注或造成例句不必要換行。
- 圖片需求表需記錄候選頁、是否補圖與理由；未通過空間與必要性檢查者不列入 prompt。

## 3. Prompt 規則

- 每個 prompt 最多 16 張圖；超過 16 張必須拆批。
- Contact sheet 需寫明排列方式，例如 `4 by 4`、`2 by 5`、`3 by 4`。
- Contact sheet 需使用 row-major order，並在 prompt 中逐格列出內容。
- 圖片中的文字、字母、數字、標籤或字幕依教師指定與圖片需求表為準；未指定時，prompt 不主動加入可讀文字。
- 頁面需要的中文、越南語、拼音與頁碼，優先由 HTML 投影片排版；若教師指定圖片內文字，需在需求表與 prompt 中寫清楚。
- 同一課圖片需使用一致教材風格：柔和線稿、低飽和色、乾淨背景、適合課堂投影。
- KN2 圖片優先選具體物品、明確動作、校園生活、日常生活、交通、購物、健康、旅行等情境。
- SVG 替換圖不可保留 SVG 內原本的簡化符號感；除非教師指定 icon 風格，應改成自然教材插圖或清楚物件圖。
- 接頭、手機、文件、招牌、地圖、車票、咖啡杯等物件上若模型容易生成字樣，未指定文字時，prompt 需強調物件表面保持乾淨。

### 單張圖 Prompt 模板

```text
Create one educational textbook-style illustration for a Chinese speaking class slide.

Subject:
{{subject_description}}

Style:
Soft textbook line-art, thin grey-blue outlines, muted pastel fills, white or very pale grey background, gentle flat shading, subtle low-contrast shadows, clean uncluttered composition, natural human proportions when people appear.

Composition:
{{composition_and_crop_note}}

Important:
Do not add readable text, letters, numerals, Chinese characters, labels, captions, or watermarks unless they are explicitly specified in the image request table.
```

### Contact Sheet Prompt 模板

```text
Create one square {{cols}} by {{rows}} contact sheet image for a Chinese speaking class slide deck.
This prompt contains exactly {{image_count}} images. Each cell is a separate textbook-style illustration.

Style:
Soft educational textbook line-art, thin grey-blue outlines, muted pastel fills, white or very pale grey background, gentle flat shading, subtle low-contrast shadows, clean uncluttered composition, natural human proportions when people appear.

Use exactly this row-major order, one subject per cell:

1. {{subject_01}}
2. {{subject_02}}
3. {{subject_03}}
4. {{subject_04}}
5. {{subject_05}}
6. {{subject_06}}
7. {{subject_07}}
8. {{subject_08}}
9. {{subject_09}}
10. {{subject_10}}
11. {{subject_11}}
12. {{subject_12}}
13. {{subject_13}}
14. {{subject_14}}
15. {{subject_15}}
16. {{subject_16}}

Important:
Keep every cell visually separate with narrow white gutters.
Do not add readable text, letters, numerals, Chinese characters, labels, captions, or watermarks unless they are explicitly specified in the image request table.
```

若圖片少於 16 張，刪除多餘編號並把 `{{image_count}}` 改成實際張數。

## 4. 生成與下載

1. 依圖片需求表分組，先寫出每組 prompt。
2. 將圖片需求表與完整 prompt 交給教師審核；未收到明確確認前停止。
3. 教師確認後，首次使用或更換生圖方式時確認是否同意由助理操作 ChatGPT 生圖；同一素材與同一操作已有有效授權時沿用，不重複詢問。未取得明確同意前停止。
4. 若使用 ChatGPT 網頁版，先確認目前工作階段已獲授權且圖片生成功能可用；不需讀取或記錄帳號、設定檔或登入資料。若授權或功能無法確認，立即停止，不貼 prompt。
5. 正式教材圖片只使用 ChatGPT 生成；不得改用其他自動生圖工具。Codex 內建 `image_gen` 只有在教師／使用者明確核可時才可作為例外操作；未核可前，即使圖片需求表與 prompt 已確認，也不得使用 `image_gen` 生圖。
6. 下載原始生成圖，不直接覆蓋裁切圖。
7. 下載後的圖片不得長期留在 `Downloads`；需立即移到該課對應的素材整理資料夾，並依 PPT 頁碼、頁型或用途重新命名。
8. 原圖存放：

```text
KN2課堂PPT/{{lesson_folder}}/素材整理/generated/raw/
```

若資料夾不存在，需先建立：

```text
KN2課堂PPT/{{lesson_folder}}/素材整理/generated/raw/
KN2課堂PPT/{{lesson_folder}}/素材整理/generated/cropped/
```

9. 原圖命名需能追溯批次與 PPT 對應位置，例如：

```text
slide-01-cover-raw.png
contact-sheet-a-slide-02-warmup-story-raw.png
contact-sheet-b-slide-39-picture-flashcards-raw.png
contact-sheet-c-vocab-supplement-raw.png
```

## 5. 裁切與命名

裁切後單張素材存放：

```text
KN2課堂PPT/{{lesson_folder}}/素材整理/generated/cropped/
```

命名規則：

```text
slide-{{page}}-{{role}}-{{keyword}}.png
```

例：

```text
slide-01-cover.png
slide-02-warmup-story-movie.png
slide-08-vocab-sports-meet.png
slide-39-picture-flashcard-coffee.png
```

裁切 contact sheet 時需注意：

- 依 prompt 的 row-major order 對應頁碼與檔名。
- 每張裁切圖的檔名需能看出「頁碼 + PPT 區塊／用途 + 內容」，避免只用 `image1.png`、`crop-a.png` 這類無法追蹤的名稱。
- 裁切框不得吃到相鄰格圖片。
- 若格子之間有白色 gutter，裁切框應落在白色 gutter 內側或剛好以白色邊界為準。
- 裁切後逐張快速預覽，確認沒有相鄰圖片殘邊。
- 若發現切到隔壁格、人物邊、物品邊或背景殘線，需從原始 contact sheet 重新裁切該圖；舊產生器路線再重建輸出，editor 路線用「替換圖片」更新已嵌入的圖片，下載 `.slides.json` 後重新開啟驗證受影響頁。
- 不要只在 HTML 中用 `object-fit` 隱藏錯誤裁切；裁切檔本身需乾淨。

## 6. 加入投影片（依使用路線）

只有在教師確認裁切素材後，才可進入本節。

### editor 路線

將確認後的 cropped 圖片加入已由教材包生成的 editor 對應 `item`／頁面，補記圖片來源與用途，若圖片改變課程內容則使受影響 `item` 核對失效；位置、尺寸與樣式寫入 `layoutOverrides`。下載 `.slides.json`，重新開啟檢查圖片、位置、來源與順序，重新核對後再匯出 HTML。editor 不使用舊產生器輸出資料夾，也不以重建舊 HTML 取代 JSON 驗證。

### 舊產生器路線

將裁切後圖片複製到輸出素材：

```text
ai-teaching-material-system-main/output/kn2/lesson-{{lesson_number}}/slides/assets/generated/
```

實作原則：

- 產生器需從該課 `素材整理/generated/cropped/` 讀取圖片，再輸出到 `slides/assets/generated/`。
- 不要在 HTML 中直接引用課程資料夾內的 `素材整理`。
- 若圖片用來取代 SVG 或 HTML/CSS 視覺元素，需確認頁面已改引用新 PNG，且該頁不再引用舊 SVG。
- 圖片檔名需和頁碼對應，方便 QA。
- HTML 中可保留 caption 文字，例如 `Type-C`、`Lightning`、`USB`；但圖片檔本身不得含字。

## 7. 版面規則

### 封面

- 封面若為左文右圖，文字欄與圖片欄固定分區。
- 右側圖片可使用 `object-fit: cover`、`object-position` 或放大裁切減少空白。
- 封面標題不可被圖片壓到；圖片不得進入左側文字安全區。

### Từ vựng 生詞頁

- 左側生詞閃卡優先保持完整。
- 右側例句、互動問句或 AB 對話優先保持可讀，不為了放圖強迫換行。
- 生詞頁圖片只在通過補圖判斷後使用；右側下方可用高度約 `140px` 以上才可考慮小圖，約 `90px` 到 `120px` 原則上不補。
- 生詞圖片放在例句或對話下方空白處。
- 圖片以 PPT 右側內容區置中：也就是閃卡右邊界到 PPT 右側安全邊界之間的可用區域中心。
- 圖片可放大，但不得遮住例句、對話、頁碼、來源文字或工具列，也不得造成例句不必要換行、字級縮小、行距壓縮或超綱標注混亂。

### 圖片造句與任務頁

- 圖片要清楚呈現目標動作或情境。
- 指令、提示詞與句型由 HTML 排版，圖片內不放文字。
- 若有 QR Code，圖片與 QR Code 不可互相擠壓。
- 四格圖片造句頁需保持四張圖大小一致、視覺風格一致，且每格圖都能直接對應該格 `Từ gợi ý`。
- 圖片造句頁的圖片不要太複雜；學生應能在 3 秒內看懂情境並說出句子。

## 8. QA 檢查（依使用路線）

### editor 路線

- 重新開啟教材包生成的 `.slides.json`，確認圖片來源已連到對應 `item`、圖片已載入、位置不遮住文字／來源／頁碼，且受影響頁的正反面與前後頁仍正確。
- 若圖片增補了題目、答案、指令或其他內容，確認 `items` 已回寫且受影響核對狀態已失效，完成教師核對後才可正式交付；單純位置／尺寸／樣式修改確認 `layoutOverrides` 保留。
- 匯出 HTML 後離線開啟，檢查受影響圖片頁；不要求舊產生器重建或 `slides/assets/generated/` 輸出。

### 舊產生器路線

重建 HTML PPT 後必查：

- 圖片是否全部載入，沒有 broken image。
- 是否仍引用應被替換的舊 SVG 或 placeholder。
- 圖片是否遮住中文、越南語、拼音、頁碼或來源文字。
- 生詞頁例句是否因圖片變窄而不必要換行。
- 生詞頁補圖是否已通過空間與必要性檢查；有補圖者右側下方可用高度原則上約 `140px` 以上，圖片未破壞超綱標注與漢字對齊。
- 封面圖片是否有過多空白，且未壓到標題。
- Contact sheet 裁切是否吃到相鄰格。
- 圖片內文字、字母、數字、標籤或字幕是否符合圖片需求表；未指定處不可出現多餘可讀文字。
- 圖片風格是否一致，且符合課堂教材感。
- 圖片造句頁四格圖是否和提示詞、答案一致。

舊產生器路線可用本機預覽截圖抽查所有有圖片的頁面；若發現問題，先修裁切或版面，再重建輸出。editor 路線檢查受影響頁的瀏覽器預覽與匯出結果即可。

## 9. 交付前確認（依使用路線）

### editor 路線

- cropped 圖片已加入 `.slides.json`，下載後可重新開啟，圖片與位置保留。
- 匯出 HTML 可離線開啟，受影響圖片頁已完成 QA；交付 `.slides.json` 與 HTML。

### 舊產生器路線

交付前需確認：

- `raw/` 保留原始生成圖。
- `cropped/` 保留裁切後單張圖。
- 下載後素材已從 `Downloads` 移入對應 lesson 的 `素材整理/generated/raw/`，且 raw / cropped 檔名都能直接對應 PPT 頁碼與用途。
- `slides/assets/generated/` 已包含實際被 HTML 使用的圖片。
- `HTML_PPT製作稿` 的圖片需求表、prompt 與實際檔名一致。
- 所有圖片頁已完成 QA。
- 已確認需要替換的 SVG、placeholder 或 HTML/CSS 暫時視覺元素不再被該頁引用。
