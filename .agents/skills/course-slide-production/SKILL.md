# KN2／KN4 投影片製作

以根目錄 `製作契約.md` 為執行依據。這份 skill 只安排工作，不複製排版數值。

## 新課或尚未套版的課

1. 先讀本課課本、教師確認紀錄、教材包（若已有）與本課所屬 KN2／KN4 的 01 架構、02 頁型模板。來源有缺漏就列出確切缺漏，先完成不依賴它的部分。舊 `HTML_PPT製作稿` 只作舊產生器或待溯源資料，不是新課的獨立入口。
2. 在 editor 教材資料庫讀取／貼上文字教材或匯入 `.lesson.json`，建立／更新 `lessonPackage`、逐頁 `sources` 與本課 `items`。需要批次抽取時才使用 `scripts/prepare_lesson_package.py`；掃描 PDF 沒有文字時明確要求 OCR，不能臆造課文、題目或答案。
3. 逐項整理 `items`：穩定 ID、題型、教學目標、教材／教師補充來源、正面、答案、超綱標注、學生指令與核對狀態。AI 或教師整理出的草稿仍須由教師核對語意、程度、題目、答案與指令；不得以自動生成結果代替核可。來源、題型、必填欄位、正反面格式、標注與版本等結構檢查通過後，按 UI「核對完成，生成 PPT」，或以可選的 `scripts/build_course.cjs` 生成可編輯 `.slides.json`。
4. 新課按 editor 的「新課程」進入教材資料庫：讀取／匯入教材、保存原頁碼與文字、整理 `items`，逐頁與逐項核對後按生成；這是正式教材先行入口，生成前畫布與格式工具保持鎖定。由教材包生成 `.slides.json` 後才作手動微調與放映。若改題目、答案、學生指令或其他內容，回寫對應 `items`／來源並使該項核對失效，重新核對後再生成；若只改位置、尺寸或樣式，寫入 `layoutOverrides`，重建不得丟失。符合 `頁碼`、`檔名`、`投影片畫面文字` 欄位的 Markdown 匯入只建立保留全部列的待溯源草稿。
5. 依使用路線做文件診斷。舊產生器路線才檢查並修正會妨礙生成的檔名、總數、Manifest 對應與已確定的重複頁碼；不自動重新編號或刪除題目。教材包／新 JSON 路線改做來源、內容核對、模型檢查與重新開啟驗證。
6. 先渲染本課最容易出問題的實際頁：長超綱例句、翻牌背面、最長對話練習、雙／三詞卡；每種使用到的新頁型至少一頁。內容已核可時，這是內部排版檢查，不是新增教師核可關卡；樣頁無溢出才批次套用同一模板。
7. 最後跑全課結構檢查與本課受影響頁型的互動檢查，交付輸出位置、測試版本、通過項目與未完成項目。圖片與 PDF 仍依已有核可範圍進行，未完成來源或核對不得正式放映／匯出。

## 已有投影片的局部修正

1. 指明課次、頁面內容識別與問題；頁碼只用來定位，先確認沒有因拆頁而改號。
2. 內容錯誤回寫本課 `items`／來源並清除受影響核對狀態，重新核對後再生成；重複排版錯誤改共用頁型；單頁特殊版面只改該頁 `layoutOverrides`。不得以全課樣式覆蓋解決單頁問題。
3. 只重建受影響頁；若增刪頁則更新整份導覽清單、頁碼與總數，保留課本來源與 `items` 穩定 ID。確認重建仍保留 `layoutOverrides`，並檢查相鄰頁及受共用模板影響的頁型。
4. 用相同畫布、字型與顯示狀態比較修改前後；記錄修正落在哪個來源檔。已解決的內容不重新設計。
5. 共用規格變更只維護 `製作契約.md`，KN2／KN4 特有教學差異仍放各自模板。未實際測試的舊 QA 勾選不能沿用。

## 拖曳編輯後的交付

下載 `.slides.json` 保存 `lessonPackage`、`sources`、`items`、投影片、`layoutOverrides`、圖片與正反面；重新開啟確認內容、位置與版面覆寫保留，再匯出獨立 HTML。內容改動未回寫並重核對前不得正式交付；版面改動不得只留在輸出 HTML。瀏覽器自動保存不取代備份，教師備註不得出現在學生放映中。PDF 只含各頁正面，不含動畫、背面答案或教師備註；需要答案版時另以明確內容製作，不宣稱互動已轉成 PDF。
